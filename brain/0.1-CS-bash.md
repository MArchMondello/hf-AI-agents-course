# 0.1 Bash — Cheat Sheet

*Part of hf-AI-agents-course-0-onboarding. Bash is the **shell**: the program that reads what you type in the terminal and runs it. It speaks its own language, not Python.*

## 1. Who am I talking to? Read the prompt

```
(.venv) <user>@<hostname>:~/PROJECTS/hf-AI-agents-course$
└──┬──┘ └─┬──┘ └───┬────┘ └─────────────┬──────────────┘│
 active  user   computer         current folder         └ $ = bash is listening
 venv                            (~ = your home)
```

| Prompt ends with | Who's listening | You type |
| --- | --- | --- |
| `$` | bash | `cd`, `ls`, `pip install`, `python file.py` |
| `#` | bash as **root** (admin), so be careful | same, but with full power |
| `>>>` | Python | `print("hi")`, `import os` |
| `...` | Python, waiting for you to **finish** a statement | the rest of it, or Enter on an empty line |
| `PS C:\...>` | **PowerShell** (Windows), not bash | `wsl` to switch to bash |

Python code typed at `$` → errors like `Command 'from' not found`. **No error doesn't mean it worked**: `x=5` is valid bash, but it does something else. In PowerShell, `~` means `C:\Users\<windows-user>`, not your Linux home.

## 2. Going into Python and back out

```
 bash  $  ──── python ────▶  >>>  Python
       ◀── exit()  or  Ctrl+D ──
```

| Situation | Do this |
| --- | --- |
| Enter Python | `python` |
| Leave Python | `exit()` + Enter, or **Ctrl+D** |
| Stuck on `...` | **Ctrl+C** to cancel the unfinished line, then `exit()` |
| A program is running and won't stop | **Ctrl+C** |
| Run a file without entering the REPL | `python file.py` (from `$`) |
| A quick one-liner from bash | `python -c "print('hi')"` |

**Pasting code into `>>>`:**

- Start every top-level line at the **left edge**. Leading spaces → `IndentationError: unexpected indent`. Code copied from tutorials is often indented: remove those spaces.
- Paste a multi-line statement **all at once**. Python shows `...` until the brackets close.
- Indentation **inside** brackets or blocks is fine. Only the *first* line must not be indented.
- More than a few lines? Put them in a `.py` file and run `python file.py`.

Leaving Python doesn't leave the venv: `(.venv)` is still there afterwards.

## 3. Moving around

```bash
pwd                 # print working directory: where am I?
ls                  # list files
ls -la              # list ALL (incl. hidden .files) with details
cd folder           # go into folder
cd ..               # go up one level
cd ~                # go home (also just: cd)
cd -                # go back to the previous folder
```

| Symbol | Meaning |
| --- | --- |
| `/` | root of the whole filesystem |
| `~` | your home: `/home/<user>` |
| `.` | this folder |
| `..` | parent folder |
| `.name` | a hidden file/folder (e.g. `.venv`, `.bashrc`) |

**Tab completion:** type the first letters, then press **Tab**. Bash finishes the name for you. Use it constantly.

## 4. Files and folders

```bash
mkdir name              # make a folder
mkdir -p a/b/c          # make nested folders (no error if they exist)
touch file.py           # create an empty file
cp src dst              # copy a file
cp -r src/ dst/         # copy a folder (-r = recursive)
mv old new              # move OR rename (nothing is lost)
rm file                 # delete a file
rm -r folder            # delete a folder and everything inside
```

**`rm -rf` deletes forever.** There's no recycle bin and no "are you sure?". Read what comes after it **every time** before pressing Enter.

## 5. Looking inside files

```bash
cat file            # print the whole file
less file           # scroll through it (q to quit, /word to search)
head -n 20 file     # first 20 lines
tail -n 20 file     # last 20 lines
tail -f log.txt     # follow a file live as it grows (Ctrl+C to stop)
nano file           # simple editor: Ctrl+O save, Ctrl+X exit
code .              # open this folder in VS Code (from WSL)
```

## 6. Finding things

```bash
which python                # which program runs when I type "python"?
which -a code               # ALL matches, in PATH order
find . -name "*.py"         # find files by name, starting here
grep -rn "LiteLLM" .        # search text inside files, with line numbers
du -sh folder               # how big is this folder?
df -h                       # how much disk space is left?
```

## 7. Combining commands: pipes and redirects

| Symbol | Meaning | Example |
| --- | --- | --- |
| `\|` | send output into the next command | `ls -la \| grep venv` |
| `>` | write output to a file (**overwrites**) | `pip freeze > requirements.txt` |
| `>>` | append output to a file | `echo "x" >> notes.txt` |
| `&&` | run the next command only if this one succeeded | `cd proj && source .venv/bin/activate` |
| `;` | run the next command regardless | `cd proj; ls` |

## 8. Installing and admin (Ubuntu)

```bash
sudo apt update                 # refresh the list of available packages
sudo apt install -y name        # install a system program
sudo apt upgrade                # upgrade everything
curl -fsSL <url> | bash         # download a script and run it (only from sources you trust)
```

- `sudo` = "do this as admin". It asks for your password (typing shows nothing, which is normal).
- Use `sudo` for **system** stuff (`apt`). **Never** for `pip`: use a venv.
- When a command line suggests a fix ("Command not found, but can be installed with…"), read it first: it may reinstall something you removed on purpose.

## 9. Running programs and stopping them

```bash
python script.py        # run a program
Ctrl+C                  # STOP the running program
Ctrl+D                  # end input / exit a shell or Python REPL
ps aux | grep ollama    # is a program running?
kill 1234               # stop process number 1234
systemctl status ollama # status of a background service
```

## 10. Keyboard shortcuts that save time

| Keys | Does |
| --- | --- |
| **Tab** | autocomplete names |
| **↑ / ↓** | previous / next command from history |
| **Ctrl+R** | search your command history |
| **Ctrl+A / Ctrl+E** | jump to the start / end of the line |
| **Ctrl+U** | delete the whole line before the cursor |
| **Ctrl+L** | clear the screen (also: `clear`) |
| **Ctrl+C** | cancel/stop. In bash it does **not** copy |
| **Ctrl+Shift+C / V** | copy / paste in Windows Terminal (or right-click to paste) |

Plain Ctrl+V in bash means "insert the next key literally", which is why it doesn't paste.

## 11. Variables, PATH and the environment

```bash
NAME="Ada"            # set a variable (no spaces around =)
echo $NAME              # use it
echo $PATH | tr ':' '\n'  # folders bash searches for commands, one per line
export API_KEY="abc"    # make it visible to programs you start (e.g. Python)
hash -r                 # forget remembered command locations (after install/uninstall)
```

- `PATH` is how a venv works: `activate` puts `.venv/bin` at the front.
- Settings you want in **every** terminal go in `~/.bashrc`, then run `source ~/.bashrc`. Example (Claude Code): `echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc` (run once only).

## 12. Getting help

```bash
command --help          # quick help for most commands
man command             # full manual (q to quit)
type command            # is it a program, a built-in, or an alias?
```

## 13. WSL specials (Windows ↔ Linux)

```bash
explorer.exe .          # open the current folder in Windows Explorer
cd /mnt/c/Users/...     # reach the Windows C: drive from Linux
code .                  # open the folder in Windows VS Code, connected to WSL
```

```powershell
wsl --shutdown          # (in PowerShell) fully restart WSL, e.g. after Windows PATH changes
```

- Keep projects in `~/...` (the Linux side). It's faster than `/mnt/c`.
- From Windows, the Linux files are at `\\wsl.localhost\Ubuntu\home\<user>`.
- VS Code is connected when the title says `[WSL: Ubuntu]` and the bottom-left shows `>< WSL: Ubuntu`. If not: `><` → Reopen Folder in WSL.
- Boxes instead of symbols ("tofu") = the old console window's font. Use Windows Terminal or VS Code's terminal.

## 14. Habits of a calm terminal user

1. **Read the prompt** before typing: which folder, which venv, `$`, `>>>`, `...` or `PS`?
2. **Paste one command at a time.** Don't paste `#` comment lines. A busy command (like `apt`) can swallow the lines pasted after it.
3. **Read error messages and installer notes.** They usually say exactly what went wrong and how to fix it.
4. **Use Tab** instead of typing long names.
5. **Pause before `rm`, `sudo` and `>`**, since these can destroy things.
6. **Longer than one line of Python? Put it in a `.py` file** and run `python file.py`.
