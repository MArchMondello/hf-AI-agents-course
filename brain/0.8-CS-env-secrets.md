# 0.8 Secrets in a `.env` File — Cheat Sheet

*Part of hf-AI-agents-course-0-onboarding. Tokens live in one private file, outside every git repo; the code reads them by name and never contains them.*

## ⭐ The one thing you'll do most

```python
import os
from dotenv import load_dotenv

load_dotenv()                              # finds ~/PROJECTS/.env by searching upwards
token = os.getenv("HF_TOKEN_READ")         # read by NAME: the value never appears in the code
```

## 1. The big idea in one picture

```
~/PROJECTS/
├── .env                       ← the secrets: ONE file, outside every repo (chmod 600)
├── CLAUDE.md
└── hf-AI-agents-course/       ← git repo (public on GitHub)
    ├── .gitignore             ← contains .env anyway: a second safety net
    └── 1.weather-agent-lab.ipynb
              │
              │ load_dotenv(): is there a .env here? no → go up one folder → yes: ~/PROJECTS/.env
              ▼
        os.environ["HF_TOKEN_READ"] = "hf_..."   (only in memory, only for this Python process)
```

| Word | Meaning | Analogy |
| --- | --- | --- |
| **environment variable** | a `NAME=value` pair that a running program receives from outside; Python reads it with `os.getenv("NAME")` | a note pinned on the site office board: every worker can read it, it is not in the drawings |
| **`.env`** | a plain text file of `NAME=value` lines. Not special to the system: only `python-dotenv` reads it | the key cabinet in the site office |
| **`load_dotenv()`** | (package `python-dotenv`) copies the `.env` lines into `os.environ` of the running program | taking the keys out for today's work |
| **token / API key** | a password for programs: whoever has it acts as you, and spends your credit | the master key of the building |
| **scope / permissions** | what a token is allowed to do: only read, call inference, write… | a key that opens only the storage room |
| **placeholder** | `NAME=` with an empty value: the slot exists, the secret is not there yet | an empty hook with a label on it |

## 2. Create the `.env` (once)

```bash
# --- 1. Go to the folder ABOVE the repos ---
cd ~/PROJECTS

# --- 2. umask 077 = the new file is readable only by you (like chmod 600) ---
umask 077
cat > .env <<'EOF'
# --- 1. Hugging Face (hf.co/settings/tokens) ---
HF_TOKEN_READ=
HF_TOKEN_INFERENCE=

# --- 2. Anthropic (console.anthropic.com) ---
ANTHROPIC_API_KEY=
EOF

# --- 3. Check: -rw------- means only you can read and write ---
ls -la .env
```

**The template in the repo: `.env.example`.** Same names, empty values, **committed**: it tells whoever clones the repo which secrets are needed. `.env` holds the values and is never committed.

| File | Read by | Contains | In git? |
| --- | --- | --- | --- |
| `requirements.txt` | pip | packages to install | ✅ |
| `.env.example` | people | the **names** of the secrets | ✅ |
| `.env` | `load_dotenv()` | the **values** | ❌ never |

```bash
# --- New machine / new clone: start from the template ---
cp .env.example .env                  # or to ~/PROJECTS/.env, to share it
git check-ignore -v .env              # must print the .gitignore line
git check-ignore -v .env.example      # must print NOTHING: the template is committed
```

`requirements.txt` is the bill of materials to order; `.env.example` is the key board with labels and empty hooks.

**Why outside the repo:** `~/PROJECTS` is not a git repo, so `git add` can never pick the file up, whatever happens to a `.gitignore`. And all the projects share it: one token, one place to update it.

## 3. Our token names

| Name | What for | Where to get it |
| --- | --- | --- |
| `HF_TOKEN_READ` | download models and datasets; the course's `InferenceClient` examples | hf.co/settings/tokens → **Create new token** → type **Read** |
| `HF_TOKEN_INFERENCE` | calls to HF **Inference Providers** (e.g. smolagents' `InferenceClientModel`) | hf.co/settings/tokens → **Create new token** → type **Fine-grained** → tick *Make calls to Inference Providers* |
| `ANTHROPIC_API_KEY` | the Claude API (`BACKEND = "claude"`) | console.anthropic.com → **API Keys** → **Create Key**. Needs API credit: a claude.ai plan is not enough |
| `E2B_API_KEY` (later) | E2B code sandboxes | e2b.dev dashboard → API keys (see `1.5-CS-sandbox-approaches.md`) |

**One token, one job.** Two HF tokens instead of one: if a token leaks, the damage is limited to what it can do, and you revoke only that one. A key for the storage room, a key for the office.

**Who reads what by itself:**

| Library | Looks for automatically | With our names |
| --- | --- | --- |
| `anthropic` | `ANTHROPIC_API_KEY` | ✅ same name: `anthropic.Anthropic()` just works after `load_dotenv()` |
| `huggingface_hub`, `smolagents` | `HF_TOKEN` (or a saved `hf auth login`) | ❌ different name, on purpose: pass it explicitly, `token=os.getenv("HF_TOKEN_READ")` |
| `e2b` | `E2B_API_KEY` | ✅ same name |

Passing the HF token explicitly is a feature: the code says **which** token it uses, and the more powerful one is never used by accident.

## 4. Fill in the tokens (safely)

```bash
# --- 1. Open the file in the editor, paste each value after the = ---
code ~/PROJECTS/.env
```

- Paste the value **in the editor**, nowhere else. Not in a terminal command (`echo 'HF_TOKEN_READ=hf_...' >> .env` ends up in `~/.bash_history`), not in a chat, not in a notebook cell (cells are saved with the file, outputs too).
- `NAME=value`: no spaces around `=`, no quotes needed.
- Save (`Ctrl+S`) and close the tab.

## 5. Check it without showing it

```python
# --- Prints only "set (N chars)" / "empty" / "missing": never the value ---
import os
from dotenv import load_dotenv, find_dotenv

print("file:", find_dotenv())
load_dotenv()
for name in ["HF_TOKEN_READ", "HF_TOKEN_INFERENCE", "ANTHROPIC_API_KEY"]:
    v = os.getenv(name)
    print(name, "missing" if v is None else "empty" if v == "" else f"set ({len(v)} chars)")
```

Never `print(token)`, not even "just to check": a notebook saves its outputs, and the output goes to GitHub with the notebook.

## 6. How `load_dotenv()` finds the file

| Rule | Consequence |
| --- | --- |
| it searches the current folder, then each parent folder, and takes the **first** `.env` it finds | a `.env` inside a repo **hides** `~/PROJECTS/.env`. One file only |
| it does **not** overwrite variables already set in the shell (`override=False`) | if you `export HF_TOKEN_READ=...` in bash, that one wins |
| it reads the file **when called** | changed the `.env`? Restart the kernel, then run `load_dotenv()` again |

Checked on this setup: from the repo folder, `find_dotenv()` returns `~/PROJECTS/.env` from a script, from `python -c` and from IPython.

## 7. If a token leaks

1. **Revoke it at once:** hf.co/settings/tokens → the token's menu → *Invalidate* (or delete); console.anthropic.com → API Keys → delete.
2. Create a new one and paste it into `.env`.
3. If it was committed: removing it in a new commit is **not enough**, it stays in the git history. A revoked token is harmless; that's why step 1 comes first.

## 8. Common errors → fixes

| Error | Meaning | Fix |
| --- | --- | --- |
| `os.getenv(...)` returns `None` | `load_dotenv()` not called, or the name is misspelled | call `load_dotenv()` first; compare the name with the `.env` letter by letter |
| it returns `''` | the placeholder is still empty | fill in the value in `~/PROJECTS/.env` |
| `401 Unauthorized` from Hugging Face | no token passed: the library looked for `HF_TOKEN`, which we don't use | `token=os.getenv("HF_TOKEN_READ")` (or `_INFERENCE`) |
| `403` from HF Inference Providers | the token lacks the inference permission | use `HF_TOKEN_INFERENCE` (fine-grained, *Make calls to Inference Providers*) |
| changed the `.env`, nothing changes | the kernel still has the old values | restart the kernel, run `load_dotenv()` again |
| a different token is used than expected | a `.env` inside the repo hides the shared one, or a variable was exported in the shell | `print(find_dotenv())`; `env \| grep TOKEN` (shows values: only in your own terminal) |
| `ModuleNotFoundError: No module named 'dotenv'` | `python-dotenv` not installed in this `.venv` | `pip install python-dotenv` (already in `requirements.txt`) |
| new secret added to `.env`, but a fresh clone doesn't know it exists | `.env.example` not updated | add the name (empty value) to `.env.example` too, and commit |
| `.env` shows up in `git status` | it is inside a repo and not ignored | move it to `~/PROJECTS/`, or add `.env` to `.gitignore` |
