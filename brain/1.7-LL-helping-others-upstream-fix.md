# 1.7 Lesson: Helping Others — an Upstream Fix, and the Review that Made It Right

*Part of hf-AI-agents-course-1-agents. Follow-up of [1.6](1.6-CS-hf-space-first-agent.md). My copy of the course's First Agent Template answered every question with a bare "Error"; I fixed it, then gave the fix back to everyone who duplicates the template. 21–22 Nov 2026.*

## 1. The big idea in one picture

```
agents-course/First_agent_template  (UPSTREAM: not mine, read-only for me)
 ├── main                           ← what every student duplicates
 ├── refs/pr/789  ◀── my PR: one commit, 2 files, 3 lines ──┐
 └── Community: discussions + PRs                           │
       └── #364 "Why am I getting Error…" ◀── my comment ───┤ "PR with the same change: …/789"
                                                            │
<hf-user>/First_Agent_Template  (MY duplicate)              │
 └── main  ← fix committed and tested here FIRST ───────────┘ (same 3 lines)
```

**A fix that works on my machine helps one person. The same fix, posted where others look, written so they can trust it and check it, helps everyone who hits the bug after me.**

| Word | Meaning | Analogy |
| --- | --- | --- |
| **upstream** | the original repo that others copy (here: `agents-course/First_agent_template`) | the standard detail published by the manufacturer |
| **duplicate** | your own copy of a Space (HF's "Duplicate this Space"); no link back to upstream | the detail copied into your own project |
| **pull request (PR)** on HF | a proposed change, stored as a git ref `refs/pr/N`, listed in the **Community** tab | a variation proposal left in the manufacturer's box |
| **discussion** | a thread in the Community tab: questions, answers, links | the forum where site managers ask each other |
| **dry run** | run everything except the part that publishes; print what *would* be sent | a mock-up before the real build |
| **review** | someone reads the change as its future readers will, before it goes out | the second architect who checks the drawings before they go to the client |

## 2. The story

| Step | What happened |
| --- | --- |
| 1 | My duplicate answered everything with a bare **Error** |
| 2 | The **Logs** showed two errors in cascade: a provider 400 (`Type mismatch of '/messages/0/content'`), hidden by a `TypeError` in `Gradio_UI.py` (diagnosis in [1.6](1.6-CS-hf-space-first-agent.md)) |
| 3 | Reproduced locally with the Space's own versions, three variants, one change each; the whole agent run with the fix |
| 4 | Fix committed on **my** Space from the browser: logs clean, correct answers |
| 5 | Question: give it back upstream? A first draft of PR + comment was ready |
| 6 | **The review** (section 3) changed the title, the comment and the description before anything was sent |
| 7 | Sent from my machine, **no clone**: [PR #789](https://huggingface.co/spaces/agents-course/First_agent_template/discussions/789) and a [comment on #364](https://huggingface.co/spaces/agents-course/First_agent_template/discussions/364) |
| 8 | Checked what was published, file by file |

## 3. Lesson 1: before writing, check that it's worth it

| Question | How to check | My case (21 Nov 2026) |
| --- | --- | --- |
| Is the fix tested? | on **your own** duplicate, logs clean | ✅ |
| Has someone posted it already? | search the discussion **texts**, not only titles | 126 threads of the last 200 days: nobody |
| Does anyone merge PRs there? | count merged PRs | 731 PRs, **2 merged ever**, last in April 2025 |
| Where do people with this problem look? | the thread with the **same symptom** | #364: 3 comments from 2025, only "check the logs", no cause |

The first search looked only at **titles** and found nothing. That proves little: a fix usually hides in a comment. Searching the **texts** is what makes "nobody has posted it" a fact.

**Decision:** a PR **and** a comment, linked. The PR will probably never be merged; its job is to be an official, linkable diff anyone can apply. The comment is what actually helps, because it sits where people search.

## 4. Lesson 2: the review is not optional

I asked for it explicitly ("act as a senior staff engineer and HF member: am I doing the right thing, the right way?"). It confirmed the approach and changed **four** things. Each one is about the **reader**, not the code:

| # | Before the review | After | Why |
| --- | --- | --- | --- |
| 1 | title: `Fix "Error" on every question: send messages as plain text` | `Fix bare "Error" in chat: provider 400 "Type mismatch of /messages/0/content"` | people search for **the text their logs show**. "Error" alone finds nothing |
| 2 | comment starts: "In my duplicate the bare Error came from…" | starts with a **condition**: "If your Space shows a bare "Error" **and** Logs → Container contains `…`, this is the cause and the fix." | "Error" has many causes (token, credits, overloaded model): without the condition, students apply a fix they don't need |
| 3 | description: Problem · Cause · Fix · Verification | + **Scope**: "a minimal workaround for the pinned smolagents 1.13; the long-term fix is upgrading" | saying what the fix is **not** earns trust; a maintainer believes the author who states the limit |
| 4 | silent expectation: "they'll merge it" | the PR is a reference, the comment is the help; **don't chase maintainers** | 2 merges in 731 PRs: plan for the repo as it is |

Plus one thing the review **kept**: a dedicated token with the minimum permission. That was already right.

## 5. Lesson 3: write for the person who arrives from a search

| Text | Rule |
| --- | --- |
| PR title | contains the **exact error text** |
| PR description | **Problem · Cause · Fix · Verification · Scope**, with the log excerpt |
| Comment | starts with the **condition**; readable **without** opening the PR (cause, the lines to change, how to apply); the PR link at the end |
| Order | **PR first, comment second**: the comment needs the PR link |
| Size | the smallest diff that fixes it: 3 lines, no version bumps |

## 6. Lesson 4: a small permission, a dry run, a check after

**The token**: fine-grained, **one** box: *Discussions & Posts → Interact with discussions / Open PRs on external repos* (`discussion.write`). It was enough to upload the files into the PR **and** to comment. In `~/PROJECTS/.env` as `HF_TOKEN_CONTRIB` ([0.8](0.8-CS-env-secrets.md)). A pass to drop proposals in the box, not a key to the site.

**The dry run**: the same script prints the diff and sends nothing; only `--send` publishes. Each edit must match **exactly once** in the current upstream file, or the script stops: upstream may have changed since I looked.

**The check after**: the API's `diff` field came back `None`, so I compared `refs/pr/789` with `main` file by file. Result: only the 3 intended lines, same file list. The comment: last in #364, by my account, with the PR link.

```python
# --- File-by-file diff: the PR against main ---
for f in ["app.py", "Gradio_UI.py"]:
    a = open(hf_hub_download(UPSTREAM, f, repo_type="space")).read().splitlines()
    b = open(hf_hub_download(UPSTREAM, f, repo_type="space", revision="refs/pr/789")).read().splitlines()
    print(f, [l for l in difflib.unified_diff(a, b, lineterm="", n=0) if l[:1] in "+-" and l[:3] not in ("+++", "---")])
```

## 7. Three ways to open a PR on Hugging Face

| Way | When | How |
| --- | --- | --- |
| **From the website** | one file | upstream Space → Files → the file → **Contribute** → edit → *Open as a pull request* |
| **On your machine, with git** | several files | the "New Pull Request" dialog → title → **Create PR branch**, then clone and push to that `refs/pr/N` |
| **API, no clone** (what I did) | several files | `create_commit(..., create_pr=True)`, then `comment_discussion(...)` |

If you ever clone a Space, put it **next to** your repos (`~/PROJECTS/...`), not inside one with a `.gitignore`.

⚠️ The "New Pull Request" dialog opens on **any** Space, your own included: my first screenshot was on my duplicate. Check the URL says the **upstream** repo.

## 8. Takeaways

- **Test on your copy first**, then give back. Never propose an untested fix.
- **Search texts, count merges**: decide with data where your help lands.
- **The review is part of the work**, not a courtesy: all four changes were about the reader.
- **Write for the person from the search**: exact error in the title, a condition first, scope stated.
- **Minimum permission, dry run, check after**: the same discipline as a commit at work, applied to someone else's repo.

## 10. Common errors → fixes

| Error | Meaning | Fix |
| --- | --- | --- |
| `403 Forbidden` on `create_commit` or `comment_discussion` | the token lacks `discussion.write` | fine-grained token, *Interact with discussions / Open PRs on external repos* |
| `AssertionError: expected 1 match, found 0` | upstream changed since you looked | re-read the upstream file, update the edit, dry run again |
| the PR was opened on **your own** Space | the dialog/page was on your duplicate | check the repo id: `agents-course/...`, not `<hf-user>/...` |
| two identical PRs | the script ran twice with `--send` | it prints your open PRs on upstream before sending: read that line; close the extra one |
| the comment has no PR link | comment posted before the PR | PR first; the script formats the link in |
| `diff` is `None` in `get_discussion_details` | the API doesn't always fill it | compare `refs/pr/N` with `main` file by file (section 6) |
| nobody answers the PR | the repo isn't maintained | expected: the comment is what helps |
| "nobody has posted this" turns out false | only the titles were searched | search the comment **texts** too |

<summary><b>Appendix: the script, <code>upstream_pr.py</code></b> (dry run by default, <code>--send</code> to publish)</summary>

```python
"""Open ONE pull request on the course template (two files), then comment on discussion #364.

Usage:
  python upstream_pr.py            # dry run: download, patch, show the diff. Sends nothing.
  python upstream_pr.py --send     # open the PR and post the comment (needs HF_TOKEN_CONTRIB)
"""
import difflib
import os
import sys

from dotenv import load_dotenv
from huggingface_hub import CommitOperationAdd, HfApi, hf_hub_download

# --- 0. Settings ---
UPSTREAM = "agents-course/First_agent_template"
DISCUSSION = 364
SEND = "--send" in sys.argv
load_dotenv(os.path.expanduser("~/PROJECTS/.env"))

# --- 1. The exact edits: (file, old, new). Each old text must appear exactly once ---
EDITS = [
    ("app.py",
     "custom_role_conversions=None,\n)",
     "custom_role_conversions=None,\nflatten_messages_as_text=True,  # providers like Cloudflare accept only string content\n)"),
    ("Gradio_UI.py",
     "total_input_tokens += agent.model.last_input_token_count\n",
     "total_input_tokens += agent.model.last_input_token_count or 0\n"),
    ("Gradio_UI.py",
     "total_output_tokens += agent.model.last_output_token_count\n",
     "total_output_tokens += agent.model.last_output_token_count or 0\n"),
]

PR_TITLE = 'Fix bare "Error" in chat: provider 400 "Type mismatch of /messages/0/content"'
PR_DESCRIPTION = '''## Problem
In a fresh duplicate of this template, every question returns a bare **Error** in the chat.

## Cause
Two errors in cascade (from the container logs):

1. **Provider 400.** smolagents 1.13 sends each message's `content` as a list of blocks
   (`[{"type": "text", "text": ...}]`). The HF router forwards the call to Cloudflare,
   which only accepts string content:
   ```
   Bad request: 'Provider returned error', code 400, provider_name: 'Cloudflare'
   Type mismatch of '/messages/0/content', 'string' not in 'array'
   ```
2. **UI crash hides the real error.** After the failed call, `last_input_token_count` is `None`,
   so `Gradio_UI.py` line 145 raises
   `TypeError: unsupported operand type(s) for +=: 'int' and 'NoneType'`
   and Gradio shows only "Error".

## Fix
- `app.py`: `flatten_messages_as_text=True` in `HfApiModel`. Every provider accepts plain-text
  content, and the router stays free to choose one.
- `Gradio_UI.py` (lines 145-146): `... or 0`, so a failed step is reported instead of crashing the UI.

Three lines in total, no version bumps.

## Scope
This is a minimal workaround for the pinned `smolagents==1.13.0`. The long-term fix would be
upgrading smolagents (`HfApiModel` is now `InferenceClientModel`, with a built-in `GradioUI`),
which touches more files; I kept this PR small so it stays easy to review.

## Verification
- Reproduced locally with `smolagents==1.13.0` and the same model: the unmodified call fails with
  the same 400; with `flatten_messages_as_text=True` it succeeds.
- Applied to my duplicate: "what is the time in Berlin?" answers correctly, with no errors in the logs.
'''

COMMENT = '''If your Space shows a bare "Error" and **Logs → Container** contains
`Type mismatch of '/messages/0/content', 'string' not in 'array'`, this is the cause and the fix.

In my duplicate the bare "Error" came from two errors in cascade:

1. The model call fails with a **400 from the provider** (Cloudflare):
   `Type mismatch of '/messages/0/content', 'string' not in 'array'`.
   smolagents 1.13 sends message content as a list of blocks, and that provider only accepts a string.
2. `Gradio_UI.py` then crashes on `last_input_token_count` being `None`, which hides error 1.

**Fix (3 lines):**

`app.py`, inside `HfApiModel(...)`:
```python
flatten_messages_as_text=True,
```

`Gradio_UI.py`, lines 145-146:
```python
total_input_tokens += agent.model.last_input_token_count or 0
total_output_tokens += agent.model.last_output_token_count or 0
```

Commit, wait for the Space to be Running, ask again. Verified on my copy.
PR with the same change: {pr_url}
'''

# --- 2. Download the CURRENT upstream files and patch them in memory ---
read = HfApi(token=os.getenv("HF_TOKEN_READ"))
files = {}
for name in sorted({f for f, _, _ in EDITS}):
    path = hf_hub_download(UPSTREAM, name, repo_type="space", token=os.getenv("HF_TOKEN_READ"))
    files[name] = {"old": open(path).read()}
    files[name]["new"] = files[name]["old"]
for name, old, new in EDITS:
    count = files[name]["new"].count(old)
    assert count == 1, f"{name}: expected 1 match, found {count}: upstream changed, stop"
    files[name]["new"] = files[name]["new"].replace(old, new)

# --- 3. Show the diff: this is exactly what the PR will contain ---
for name, f in files.items():
    diff = difflib.unified_diff(f["old"].splitlines(), f["new"].splitlines(),
                                f"a/{name}", f"b/{name}", lineterm="", n=1)
    print("\n".join(diff))

open_prs = [d for d in read.get_repo_discussions(UPSTREAM, repo_type="space", author=read.whoami()["name"])
            if d.is_pull_request and d.status == "open"]
print(f"\nmy open PRs on {UPSTREAM}: {[d.num for d in open_prs] or 'none'}")

if not SEND:
    print("\nDRY RUN: nothing sent. Run with --send to open the PR and post the comment.")
    sys.exit(0)

# --- 4. Open the PR (one commit, both files) ---
token = os.getenv("HF_TOKEN_CONTRIB")
assert token, "HF_TOKEN_CONTRIB is missing or empty in ~/PROJECTS/.env"
api = HfApi(token=token)
info = api.create_commit(
    repo_id=UPSTREAM, repo_type="space", create_pr=True,
    operations=[CommitOperationAdd(path_in_repo=n, path_or_fileobj=f["new"].encode()) for n, f in files.items()],
    commit_message=PR_TITLE, commit_description=PR_DESCRIPTION,
)
print("PR:", info.pr_url)

# --- 5. Comment on the discussion, with the PR link ---
api.comment_discussion(UPSTREAM, DISCUSSION, COMMENT.format(pr_url=info.pr_url), repo_type="space")
print(f"comment posted: https://huggingface.co/spaces/{UPSTREAM}/discussions/{DISCUSSION}")
```
