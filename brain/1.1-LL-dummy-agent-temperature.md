# 1.1 Lesson: The Dummy Agent — Temperature, Memory and Invented Observations

*Part of hf-AI-agents-course-1-agents. Based on `1.dummy_agent_library.ipynb` (step 4: the call **without** `stop`) with local Qwen2 7B via Ollama, 18 Nov 2026.*

## 1. The experiment

Same `messages` every time: the course's `SYSTEM_PROMPT` (one tool, `get_weather`, and the Thought → Action → Observation format) plus the question *"What's the weather in London?"*. No `stop`, so the model is free to write past the Action. Only `temperature` changed.

```python
print(chat(messages, max_tokens=200))   # same input, run several times
```

## 2. What Qwen wrote

| Run | `temperature` | After the Action, Qwen wrote… | Verdict |
| --- | --- | --- | --- |
| 1 | 1 | `Observation:` and stopped | correct: waits for the real tool |
| 2 | 1 | *"Observation: I am unable to execute actions in real-time…"*, then a `Final Answer` describing what the answer *would* contain | honest, but an empty answer |
| 3 | 1 | *"Observation: Weather data for London, UK."*, then *"Final Answer: The current weather in London is [insert weather information…]"* | **invented Observation** |
| 4 | 2 | *"Observation: I am waiting for the result from the API."* … *"Observation: Query sent successfully."*, then a placeholder `Final Answer` | **two invented Observations**, and a malformed JSON (below) |

## 3. Lesson 1: the model has no memory, the dice do the work

The answers changed between runs, but Qwen wasn't "learning" or "trying something new". Every call sends the **same** `messages` and the model starts from zero.

The difference comes from **`temperature`**. At each token the model has a ranking of likely next tokens:

| `temperature` | What happens | Analogy |
| --- | --- | --- |
| `0` | always the top token → same output every run | a pianist reading the score |
| `1` | samples from the model's **real** probabilities | improvising, but only where the score leaves room |
| `2` | probabilities are **flattened**: 1% tokens become likely | improvising over everything |

**Why even `temperature=1` stayed on format:** with a strict format and an example, the model is almost certain about most tokens (`get_weather` after `"action": "` might be 98%). The dice matter only where it is **uncertain**, and the runs split exactly there: right after `Observation:`.

## 4. Lesson 2: Qwen doesn't invent facts, it invents events

In no run did Qwen invent weather data ("15°C, cloudy"). But in runs 3 and 4 it invented **protocol events**: an Observation that never happened, *"Query sent successfully"* with no query sent.

For an agent this is the more dangerous lie. The program can't tell a fake Observation from a real one: both are just text after `Observation:`.

**The fix is not to trust the model to stop: we stop it.**

```python
output = chat(messages, max_tokens=150, stop=["Observation:"])  # cut before it can invent
```

Then *we* run `get_weather(...)` and send the real result back as a new `user` message.

## 5. Lesson 3: the model copies the prompt, mistakes included

- **Double braces `{{ }}`.** The course's `SYSTEM_PROMPT` contains `{{` and `}}`. They are left over from a Python **template**: in `"...{x}...".format(x=...)`, `{{` is how you write a literal `{`. Our prompt is a plain string that never goes through `.format()`, so the doubled braces reach the model, which copies them, and its JSON becomes **invalid**. Fix: single braces in the prompt.
- **Schema copied into the value** (run 4). The prompt describes the argument as `args: {"location": {"type": "string"}}`. At `temperature=2` Qwen wrote `"location": {"type": "string", "value": "London"}`: it mixed the *description* of the input with the input itself. The correct value is just `"location": "London"`.

## 6. Takeaways

1. **No memory between calls.** The conversation lives in `messages`, not in the model.
2. **`temperature=0` for agents.** Formats and tool calls need repeatability, not creativity.
3. **Always `stop` before `Observation:`.** Whether the model stops by itself is a dice roll.
4. **Clean prompt, clean output.** The model imitates the examples literally, typos included.
5. **"Polite" isn't "correct".** A placeholder answer or an honest "I can't" still isn't the weather in London.
