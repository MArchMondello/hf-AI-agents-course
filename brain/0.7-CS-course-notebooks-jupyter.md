# 0.7 Course Notebooks in VS Code — Cheat Sheet

*Part of hf-AI-agents-course-0-onboarding. The course's lessons are `.mdx` pages (to read); the runnable code lives in separate `.ipynb` notebooks: clone them (don't fork), keep them out of your repo, run them in VS Code with your own `.venv`.*

## ⭐ The one thing you'll do most

Open a notebook, pick the `.venv` kernel, then **Restart** + **Run All** after every change to the setup cell.

```bash
code ~/PROJECTS/hf-AI-agents-course/agents-course/unit1/dummy_agent_library.ipynb
```

## 1. The big idea in one picture

```
github.com/huggingface/agents-course          huggingface.co/agents-course/notebooks
  units/en/unit1/*.mdx   ← the book (read)       unit1/*.ipynb   ← the exercises (run)
        │                                                │ git clone (read-only copy)
        ▼                                                ▼
  read on hf.co/learn            ~/PROJECTS/hf-AI-agents-course/
                                 ├── .gitignore          ← contains agents-course/
                                 ├── .venv/              ← the kernel: Python + packages
                                 ├── agents-course/      ← the clone: NOT in your repo
                                 └── 1.weather-agent-lab.ipynb  ← your own version: committed
```

| Word | Meaning | Analogy |
| --- | --- | --- |
| **`.mdx`** | Markdown + React components: the course pages. Not runnable | the textbook |
| **`.ipynb`** | Jupyter notebook: a JSON file of cells (Markdown or code) plus their outputs | the exercise book |
| **cell** | one block of the notebook, run on its own | one exercise |
| **kernel** | the Python process that runs the cells; keeps variables in memory between cells | the calculator that remembers the last result |
| **clone** | a local copy of someone else's repo, to read and run | a photocopy of the book |
| **fork** | your own copy **on GitHub**, to send changes back (pull requests) | your own edition of the book, in the shop window |

**Clone or fork?** Fork only if you'll push changes to it. To read and run the course notebooks a clone is enough, and the fork is just a copy in your public profile that adds nothing.

## 2. Get the notebooks (clone, not fork)

```bash
# --- 1. Clone the official notebooks INSIDE your course repo ---
cd ~/PROJECTS/hf-AI-agents-course
git clone https://huggingface.co/agents-course/notebooks agents-course

# --- 2. Keep the clone out of your repo ---
printf '\n# Official HF course notebooks (separate clone, not our code)\nagents-course/\n' >> .gitignore
git status --short          # only " M .gitignore", no agents-course/ files

# --- 3. Later: get the course's updates ---
git -C agents-course pull
```

Where is the notebook for a lesson? In the `.mdx`, look for the **"Open in Colab"** badge: its link ends with the notebook path (e.g. `unit1/dummy_agent_library.ipynb`).

**Optional: remove an old fork.** Locally just `rm -rf` the folder (check `git status` and `git log upstream/main..HEAD` first: nothing of yours inside?). On GitHub:

```bash
gh auth refresh -h github.com -s delete_repo        # gh needs the extra permission once
gh repo delete <github-user>/agents-course --yes    # permanent
```

## 3. Run a notebook in VS Code

```bash
# --- 1. Once: the Jupyter kernel package in your venv ---
cd ~/PROJECTS/hf-AI-agents-course
source .venv/bin/activate
pip install ipykernel

# --- 2. Open the notebook ---
code agents-course/unit1/dummy_agent_library.ipynb
```

VS Code needs the **Jupyter** extension (Microsoft). Then, in the notebook toolbar:

| Where | What | When |
| --- | --- | --- |
| top right: **Select Kernel** | → *Python Environments…* → the one ending in `hf-AI-agents-course/.venv/bin/python` | first time per notebook |
| ▶ left of a cell (or `Shift+Enter`) | run that cell | step by step |
| toolbar: **Run All** | run every cell in order | after any change |
| toolbar: **↻ Restart** (narrow window: under **…**), or `Ctrl+Shift+P` → *Jupyter: Restart Kernel* | wipe the kernel's memory: every variable and function is gone, so **Run All** next. The arrow next to Restart has *Restart Kernel and Run All* | after changing imports, `.env`, the prompt, or a setting like `BACKEND` |
| tab title: **●** instead of × | unsaved changes | `Ctrl+S` before asking anyone (or Claude) to read the file |

**Your own version vs. the course's.** Don't edit files inside `agents-course/`: they aren't versioned in your repo, and a `git pull` or a re-clone can wipe your notes. Copy the notebook to your repo root (e.g. `1.weather-agent-lab.ipynb`) and work there.

## 5. Common errors → fixes

| Error | Meaning | Fix |
| --- | --- | --- |
| `ModuleNotFoundError` in a cell, but `pip list` shows the package | the notebook runs a different Python | **Select Kernel** → the `.venv` one |
| "Running cells requires the ipykernel package" | `ipykernel` missing in that venv | `pip install ipykernel` in the activated `.venv` |
| a change in the setup cell has no effect | the kernel still remembers the old values | **Restart**, then **Run All** |
| `NameError: name 'chat' is not defined` | a later cell ran before the setup cell | **Run All**, or run the cells top to bottom |
| someone reads an old version of your notebook | unsaved edits (● on the tab) | `Ctrl+S` |
| `agents-course/` files in `git status` | the clone isn't ignored | add `agents-course/` to `.gitignore` |
| `401 Unauthorized` / token is `None` | `.env` not loaded or wrong name | `load_dotenv()` before the client; check the variable name |
| `HTTP 403 … needs the "delete_repo" scope` | `gh` can't delete repos by default | `gh auth refresh -h github.com -s delete_repo` |
