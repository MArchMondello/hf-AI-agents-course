# 1.6 A Hugging Face Space: the First Agent Template — Cheat Sheet

*Part of hf-AI-agents-course-1-agents. A Space is a git repo that Hugging Face turns into a running app: change a file, it rebuilds; ask a question, `app.py` runs a CodeAgent that calls a model through HF's router. Based on the course's [“Let's Create Our First Agent Using smolagents”](https://huggingface.co/learn/agents-course/unit1/tutorial) and on my duplicate of the template (`<hf-user>/First_Agent_Template`), 21 Nov 2026.*

## ⭐ The one thing you'll do most

When the App tab only says **Error**, the answer is in the **Logs**, never in the App:

```text
Space page → Logs (top bar) → Container → scroll to the last "Traceback" and read the FIRST error above it
```

```
│                                                                                        │
│  browser ──chat──▶ Gradio_UI.py ──task──▶ CodeAgent (app.py) ──messages──▶ HfApiModel  │
│     ▲                                       │  ▲                              │        │
│     └────────── answer / "Error" ◀──────────┘  └── Thought/Code/Observation   │        │
└───────────────────────────────────────────────────────────────────────────────┼────────┘
                                                                                ▼
                                            HF router (router.huggingface.co) → a provider
                                            (Featherless, Cloudflare, Together…) runs Qwen2.5-Coder-32B
                                            and bills YOUR account through the token
```

| Word | Meaning | Analogy |
| --- | --- | --- |
| **Space** | a git repo on Hugging Face that is also a hosted app | a model apartment: the drawings and the built room, at the same address |
| **template** | a public Space made to be **duplicated**: you get your own copy, files and all | the standard floor plan you copy and adapt |
| **SDK** (`gradio`) | the framework the Space runs; Gradio builds the chat page from Python | the prefabricated system the room is built with |
| **front matter** | the YAML block at the top of `README.md`: title, emoji, `sdk`, `sdk_version`, `app_file` | the title block of the drawing |
| **container** | the small Linux machine HF starts to run `app_file` (here: Python 3.13, `cpu-basic`) | the site where the room is actually built |
| **secret** | a value set in Settings, given to the container as an environment variable, never shown in the files | the key handed to the site manager, not drawn on the plan |
| **router / provider** | HF's router forwards each model call to a company that actually runs the model (a *provider*) | the general contractor who hands the job to a subcontractor |
| **Logs** | Build logs (pip install) and Container logs (what `app.py` prints, tracebacks) | the site diary |

## 2. The template, file by file

| File | What it is | Touch it? |
| --- | --- | --- |
| `README.md` | front matter (`sdk: gradio`, `sdk_version: 5.23.1`, `app_file: app.py`) + a one-line description | only the title/emoji |
| `requirements.txt` | `markdownify`, `smolagents==1.13.0`, `requests`, `duckduckgo_search`, `pandas` | pinned **old** smolagents (current: 1.26) |
| `app.py` | the agent: two example `@tool`s, the model (`HfApiModel`, `Qwen/Qwen2.5-Coder-32B-Instruct`), an image tool loaded from the Hub, the `CodeAgent`, then `GradioUI(agent).launch()` | **the course's exercise: the only file to change** |
| `Gradio_UI.py` | a copy of smolagents' old chat UI: streams each agent step into the chat | only to fix bugs |
| `prompts.yaml` | the system prompt and the planning prompts: *Thought → Code → Observation*, code ends with `<end_code>` | read it: it is ReAct, written down (see `1.0-CS-agents.md`) |
| `tools/final_answer.py`, `web_search.py`, `visit_webpage.py` | ready-made tools | `final_answer` must stay in the tools list |
| `agent.json` | an exported description of an agent (tools, model, prompts) | not used by `app.py` |

Three things in `app.py` worth knowing before changing anything:

```python
# --- 1. The model: in smolagents 1.13 it is HfApiModel (renamed InferenceClientModel in later versions) ---
model = HfApiModel(max_tokens=2096, temperature=0.5,
                   model_id='Qwen/Qwen2.5-Coder-32B-Instruct', custom_role_conversions=None)
# no token= here: HfApiModel reads the environment variable HF_TOKEN -> the Space secret

# --- 2. The tools: only final_answer is mounted. get_current_time_in_timezone is DEFINED but NOT in the list ---
agent = CodeAgent(model=model, tools=[final_answer], max_steps=6, ...)

# --- 3. The UI ---
GradioUI(agent).launch()
```

## 4. The secret: `HF_TOKEN`

```text
Settings → Variables and secrets → New secret
  Name:  HF_TOKEN                  ← exactly this name: app.py reads HF_TOKEN
  Value: the fine-grained token with "Make calls to Inference Providers"
         (on my machine the same token is called HF_TOKEN_INFERENCE, see 0.8)
```

- **Same key, different label.** The Space is another computer, with its own code: there the name must be `HF_TOKEN`. On my machine I keep my explicit names.
- **Credits belong to the account, not to the token.** Every token with the inference permission bills the same account: buying credits does not require renaming anything.
- If course code must run unchanged on my machine too, give `HF_TOKEN` as an **alias** in `~/PROJECTS/.env` (python-dotenv expands `${...}`; checked):

```bash
HF_TOKEN_INFERENCE=hf_...
HF_TOKEN=${HF_TOKEN_INFERENCE}      # alias: one value, two names
```

## 5. The bug: why the App says only "Error"

**The anecdote.** Any question ("ciao", "what is the time in Berlin?") → a red **Error** in the chat.

**The logs** (Logs → Container) show **two errors in cascade**:

```
Step 1 → Error in generating model output:
         Bad request: 'Provider returned error', code 400, provider_name: 'Cloudflare'
         "Type mismatch of '/messages/0/content', 'string' not in 'array'"
  then → Gradio_UI.py, line 145: total_input_tokens += agent.model.last_input_token_count
         TypeError: unsupported operand type(s) for +=: 'int' and 'NoneType'   ← this is the red "Error"
```

| # | What happens | Why |
| --- | --- | --- |
| 1 | the model call fails | smolagents 1.13 sends each message's `content` as a **list** of blocks (`[{"type": "text", "text": ...}]`). The router sent the call to **Cloudflare**, which accepts only a **string** |
| 2 | the UI crashes | the failed call left the token count at `None`; `Gradio_UI.py` adds it to an `int` → `TypeError` → Gradio shows a bare "Error" and hides error 1 |

**The check: reproduced on my machine** with the Space's own versions (`smolagents==1.13.0`, same model, my inference token), one change per variant:

| Variant | Change | Result |
| --- | --- | --- |
| A | none (as in the Space) | ❌ 400 from Cloudflare, same message as the logs |
| B | `provider="featherless-ai"` | ✅ |
| C | `flatten_messages_as_text=True` | ✅ |

Then the **whole agent** of `app.py` with fix C, question *"what is the time in Berlin?"*: ✅ correct answer in 4 steps (~11k input tokens, ~1k output).

**Why C, not B.** C makes every message a plain string, which every provider accepts, and leaves the router free to choose. B ties the Space to one provider staying online. One line, no new dependency.

*A detail that doesn't add up (honesty note):* the model's provider list on the Hub shows only `featherless-ai`, yet the router sent the Space's calls to Cloudflare. Fix C works whichever provider is chosen.

## 6. Apply the fix (in the browser)

```text
# --- 1. app.py: send messages as plain text ---
Files → app.py → ✏️ → in HfApiModel(...) add one argument:

    model = HfApiModel(
    max_tokens=2096,
    temperature=0.5,
    model_id='Qwen/Qwen2.5-Coder-32B-Instruct',# it is possible that this model may be overloaded
    custom_role_conversions=None,
    flatten_messages_as_text=True,  # providers like Cloudflare accept only string content
    )

→ Commit changes to main

# --- 2. Gradio_UI.py: never crash on a missing token count (so the real error reaches the chat) ---
Files → Gradio_UI.py → ✏️ → lines 145-146:

            total_input_tokens += agent.model.last_input_token_count or 0
            total_output_tokens += agent.model.last_output_token_count or 0

→ Commit changes to main

# --- 3. Wait for Building → Running, then ask again in the App tab ---
```

## 7. Linking the Space to the GitHub repo

The Space **is** a git repo (`git clone https://huggingface.co/spaces/<hf-user>/<space>`), separate from `hf-AI-agents-course` on GitHub. Ways to tie them:

| Option | How | Good | Cost |
| --- | --- | --- | --- |
| 1. Link only | the README on GitHub links to the Space | zero setup | the code lives only on HF |
| 2. Sibling clone | clone the Space next to the repo (`~/PROJECTS/<space>/`), edit in VS Code, `git push` to HF | real git workflow, diffs, commits | needs a token with **write** access to that Space |
| 3. GitHub → HF sync | the Space's files live in the GitHub repo (e.g. `spaces/first-agent/`); a GitHub Action pushes them to the Space on every push | one source of truth, portfolio on GitHub, deploy on HF | a write token as a GitHub secret, one workflow file |

Pushing needs **write** permission, which none of my current tokens has (read + inference only): a third, fine-grained token with write access to **this Space only** keeps the damage small if it leaks.

## 9. Common errors → fixes

| Error | Meaning | Fix |
| --- | --- | --- |
| App shows only **Error** | the UI crashed: the real error is earlier in the logs | Logs → Container → first error above the traceback |
| `Provider returned error … 'string' not in 'array'` (400) | smolagents 1.13 sends list content, the provider wants a string | `flatten_messages_as_text=True` in `HfApiModel` (section 6) |
| `TypeError: … 'int' and 'NoneType'` in `Gradio_UI.py` | a failed model call left the token count `None` | `... or 0` on lines 145-146 (section 6) |
| `401 Unauthorized` in the logs | no `HF_TOKEN` secret, or a misspelled name | Settings → Variables and secrets → `HF_TOKEN` |
| `403` / permission error | the token lacks *Make calls to Inference Providers* | fine-grained token with that permission |
| `402` / payment required | free inference credits used up | buy credits or use a smaller model; credits are per account |
| "the model is overloaded" / no answer | the provider is busy | another model, or the endpoint suggested in the `app.py` comment |
| a change has no effect | the Space is still building, or the edit wasn't committed | wait for **Running**; check Files → history |
| the agent ignores `get_current_time_in_timezone` | the tool is defined but not in `tools=[...]` | add it to the list (next lesson) |
| `ModuleNotFoundError` at startup | a package used in `app.py` is missing from `requirements.txt` | add it; the Build log shows what pip installed |
