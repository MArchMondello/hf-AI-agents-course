# 0.5 Publishing a Project on GitHub — Cheat Sheet

*Part of hf-AI-agents-course-0-onboarding. Publishing = turning a local folder into a public repo. Everything inside the folder ends up in the shop window, so first decide what stays in the back room, then commit, then push.*

## ⭐ The one command you'll use most

From inside a folder that already has a first commit, create the GitHub repo and upload it in one go:

```bash
gh repo create hf-AI-agents-course --public --source . --push --description "My agents, built while following the Hugging Face AI Agents Course"
```

**Write it on one line.** A line split with `\` breaks when copy-paste leaves a space after the `\` (see §8).

## 1. The big idea in one picture

```
~/PROJECTS/                  ← NOT a repo (no .git): nothing here goes online
├── CLAUDE.md                ← private notes: stay OUTSIDE every repo
├── hf-AI-agents-course/     ← repo: your work
│   ├── .git/                ← the history (created by git init)
│   ├── .gitignore           ← the bouncer: decides what Git ignores
│   ├── .venv/               ← ignored: rebuilt from requirements.txt
│   ├── brain/               ← cheat sheets: public, anonymised (§2)
│   ├── agents-course/       ← clone of the course notebooks: ignored (see 0.7)
│   ├── 0.onboarding.py      ┐
│   └── requirements.txt     ┘ committed → github.com/<github-user>/hf-AI-agents-course
└── (hf-agents-course/)      ← before: a fork of the course repo. Removed, a clone is enough (see 0.7)
```

```
folder ──(.gitignore filters)──▶ git add ──▶ git commit ──▶ gh repo create --push ──▶ GitHub (public)
```

| Word | Meaning | Analogy |
| --- | --- | --- |
| **repo** | a folder with a `.git/` inside. Git looks only from there **down**, never up or sideways | a building with its own archive |
| **`.gitignore`** | list of files Git pretends not to see. Committed, so it's public | the bouncer at the door |
| **`.git/info/exclude`** | same as `.gitignore`, but **local only**: never committed | a private note to the bouncer |
| **`requirements.txt`** | the recipe to rebuild `.venv` | the shopping list, not the fridge |
| **remote `origin`** | the GitHub copy your `git push` goes to | the shop window |
| **public** | anyone can read it, forever (copies and caches survive a delete) | a published book |

Local folder name ≠ GitHub repo name. They can differ; here we kept them equal.

## 2. Before publishing: the privacy check

What must **never** be committed:

| What | Why | How it stays out |
| --- | --- | --- |
| `CLAUDE.md`, personal notes | personal details and plans | keep in `~/PROJECTS/`, plus `CLAUDE.md` in `.gitignore` as a safety net |
| `.venv/` | heavy and tied to your machine | `.gitignore` |
| `.env` | API keys, tokens | `.gitignore` |
| drafts not ready yet | half-finished, maybe personal | keep outside the repo, or `.git/info/exclude` |
| usernames, hostname, IDs in docs | fingerprint your machine and accounts | replace with placeholders: `<user>`, `<hostname>`, `<github-user>`, `<github-id>` |

```bash
# --- 1. search for keys, tokens, email, surname (skip .venv) ---
# replace <your-name>, <your-surname>, <your-linux-user>, <your-hostname> with the real values (never commit them!)
grep -rniE "api[_-]?key|token|secret|password|hf_[A-Za-z0-9]{10,}|sk-[A-Za-z0-9]{10,}|@[a-z]+\.(com|it|de)|<your-name>|<your-surname>|<your-linux-user>|<your-hostname>" --exclude-dir=.venv .

# --- 2. see exactly what Git would commit ----------------------
git status
```

- `-r` recursive, `-n` line numbers, `-i` ignore case, `-E` allows `a|b|c`.
- Only harmless hits allowed (e.g. a comment saying `# Secrets`). `127.0.0.1` is "this computer", not private.

## 3. `.gitignore`

A plain text file: the name starts with `.` (hidden, see it with `ls -a`) and has **no extension**.

```bash
cd ~/PROJECTS/hf-AI-agents-course
cat > .gitignore << 'EOF'
# Python virtual environment (rebuilt from requirements.txt)
.venv/

# Python bytecode cache
__pycache__/
*.pyc

# Secrets: API keys, tokens
.env

# Private notes and local Claude Code settings (safety net)
CLAUDE.md
.claude/
EOF
cat -A .gitignore              # every line must end in $, not ^M$
```

- `cat > file << 'EOF' … EOF` writes everything between the two `EOF` lines into the file.
- Or in VS Code: Explorer → **New File** → `.gitignore` → paste → `Ctrl+S`.
- `cat -A` shows invisible characters: `^M$` = Windows line endings (CRLF), fix in VS Code's status bar `CRLF` → `LF`.

**Local-only ignore** (a folder you don't want to mention publicly):

```bash
echo "drafts/" >> .git/info/exclude
```

## 4. `requirements.txt`: direct dependencies only

```bash
cat > requirements.txt << 'EOF'
# Agent framework by Hugging Face, with the LiteLLM extra (needed by LiteLLMModel)
smolagents[litellm]==1.26.0

# Bridge to many LLM providers, including the local Ollama server
litellm==1.109.1
EOF
```

| Approach | Lines | Verdict |
| --- | --- | --- |
| `pip freeze > requirements.txt` | ~60, mostly dependencies of dependencies | quick, noisy |
| list only what **you** import, pinned | 2 | clean: pip finds the rest |

- `pip freeze | grep -iE "smolagents|litellm"` → the exact versions to pin.
- `[litellm]` is an **extra**: an optional part of the package.
- `==1.26.0` **pins** the version, so the code still runs a year from now.

## 5. `git init` and the first commit

```bash
# --- 1. make the folder a repo, branch called main -------------
git init -b main

# --- 2. CHECK: only the files you expect, no .venv / CLAUDE.md -
git status

# --- 3. commit -------------------------------------------------
git add .
git status                     # now green: "Changes to be committed"
git commit -m "Initial commit: first smolagents agent on local Qwen (Ollama)"
git log --oneline              # one line: hash + message
```

- `git add .` is safe **only after** checking `git status`: `.gitignore` already filtered the rest.
- The message says **what** is inside, not just "first commit". It's the first line people read on GitHub.
- `git log --stat` shows author and files: the author must be `<github-user> <…@users.noreply.github.com>` (see 0.4 §3).

## 6. Publish, then check

```bash
# --- 1. does the name already exist? (error = free, good) ------
gh repo view <github-user>/hf-AI-agents-course

# --- 2. create + push (one line, see ⭐) ------------------------
gh repo create hf-AI-agents-course --public --source . --push --description "My agents, built while following the Hugging Face AI Agents Course"

# --- 3. verify -------------------------------------------------
git remote -v                  # origin = github.com/<github-user>/hf-AI-agents-course
git status -sb                 # ## main...origin/main  → local and GitHub aligned
gh repo view <github-user>/hf-AI-agents-course --json name,visibility,description,url
```

| Flag | Does |
| --- | --- |
| `--public` | visible to everyone (the point of a portfolio) |
| `--source .` | use this folder |
| `--push` | add remote `origin` and upload the commits |
| `--description` | the sentence in the **About** box, top right on GitHub |

**Change details later** (the repo exists, so edit, don't recreate):

```bash
gh repo edit <github-user>/hf-AI-agents-course --description "My agents, built while following the Hugging Face AI Agents Course"
```

## 7. After publishing: the daily workflow

```bash
# --- rename a tracked file: git mv, so Git records the rename ---
git mv first_agent.py onboarding.py

# --- save and upload --------------------------------------------
git status
git add onboarding.py
git commit -m "Rename first_agent.py back to onboarding.py"
git push                       # origin and main are already set
```

- Before the first commit, plain `mv` is fine (Git doesn't know the file yet). After it, use `git mv`.
- Keep a file's header comment (`# onboarding.py — …`) in sync with its name.
- Drafts not ready to publish (e.g. a README) live **outside** the repo, so `git add .` can't catch them.

## 8. Common errors → fixes

| Error | Meaning | Fix |
| --- | --- | --- |
| `--description: command not found` | a space after `\` split the command: the first line ran alone (repo created **without** description) | `gh repo edit … --description "…"`; write commands on one line |
| `.venv/` listed in `git status` | `.gitignore` missing, misnamed or in the wrong folder | `ls -a`: it must be `.gitignore` in the repo root, no extension |
| `CLAUDE.md` inside the repo folder | private notes about to go public | `mv CLAUDE.md ~/PROJECTS/` **before** `git init` |
| `^M$` at line ends in `cat -A` | Windows (CRLF) line endings | VS Code status bar `CRLF` → `LF`, save |
| `GraphQL: Could not resolve to a Repository` | the repo doesn't exist on GitHub | before creating: good, the name is free |
| `Name already exists on this account` | `gh repo create` ran before (maybe half-succeeded) | check with `gh repo view`; use `git push` / `gh repo edit` instead |
| `error: remote origin already exists` | `origin` was added by a previous run | `git remote -v` to check; just `git push` |
| `Your branch is ahead of 'origin/main' by 1 commit` | committed but not pushed | `git push` |
