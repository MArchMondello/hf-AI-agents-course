# 0.4 Git & GitHub — Cheat Sheet

*Part of hf-AI-agents-course-0-onboarding. Git is the tool on your computer that keeps the history of your code. GitHub is a website that hosts Git repositories, like Azure DevOps at work. Same Git, different server.*

## ⭐ The two commands you'll use most

Get Hugging Face's latest course updates into your fork and onto your computer:

```bash
cd ~/PROJECTS/hf-agents-course
gh repo sync <github-user>/agents-course   # 1. GitHub: upstream → your fork
git pull                                   # 2. computer: your fork → local folder
```

```
huggingface/agents-course ──(1) gh repo sync──▶ <github-user>/agents-course ──(2) git pull──▶ ~/PROJECTS/hf-agents-course
```

## 1. The big idea in one picture

```
github.com/huggingface/agents-course     ← upstream: theirs, read-only for you
        │  fork (a copy on GitHub)
        ▼
github.com/<github-user>/agents-course   ← origin: yours, you can push
        │  clone (a copy on your computer)
        ▼
~/PROJECTS/hf-agents-course              ← local: where you work
```

| Word | Meaning | Analogy |
| --- | --- | --- |
| **branch** | a parallel line of work *inside* one repo (you need write access) | a new room in the company house |
| **fork** | a whole new repo on *your* account, copied from someone else's | your own house, built like the original |
| **origin** | the remote you push to (your fork) | your house |
| **upstream** | the original repo you pull updates from | their house |

You can still make branches inside your fork.

## 2. Licence check (before reusing code)

- On GitHub, **forking a public repo is always allowed**: the platform's terms say so.
- What you may **do** with the code depends on the `LICENSE` file. If there is none, the code is all-rights-reserved.
- `huggingface/agents-course` uses **Apache-2.0**: you may use, change and redistribute it, even commercially. You must keep the copyright notice and the licence, and mark the files you changed.

## 3. One-time setup (done 2026-11-17)

```bash
# --- 1. install GitHub CLI --------------------------------------
sudo apt update
sudo apt install gh -y                # apt, not "app"

# --- 2. log in ---------------------------------------------------
gh auth login
#   GitHub.com → HTTPS → Authenticate Git: Yes → Login with a web browser
#   WSL can't open a browser: open https://github.com/login/device
#   in Windows yourself and type the 8-character code shown
gh auth status                        # ✓ Logged in ... account <github-user>

# --- 3. commit identity (goes into every public commit) --------
git config --global user.name "<github-user>"
git config --global user.email "<github-id>+<github-user>@users.noreply.github.com"
git config --global --list            # check
```

**Login ≠ identity.** `gh auth login` decides *who may push*. `user.name` / `user.email` are *written inside each commit* and become public.

**Private email:** GitHub → https://github.com/settings/emails (sidebar group **Access → Emails**):
- ☑ **Keep my email addresses private** → shows your `ID+username@users.noreply.github.com`
- ☑ **Block command line pushes that expose my email**

**Check the number in the noreply address:** `gh api user --jq .id` must match the digits before the `+`. A wrong number means GitHub won't link your commits to your profile.

## 4. Fork + clone into a folder you choose

```bash
gh repo fork huggingface/agents-course --clone=false          # fork on GitHub only
gh repo clone <github-user>/agents-course ~/PROJECTS/hf-agents-course
cd ~/PROJECTS/hf-agents-course
git remote -v                         # origin = <github-user>, upstream = huggingface
```

`gh repo clone` notices that the repo is a fork and adds `upstream` by itself.
Shortcut when the default folder name is fine: `gh repo fork huggingface/agents-course --clone`.

## 5. Folder layout

```
~/PROJECTS/
├── hf-AI-agents-course/   ← your code (onboarding.py, .venv)
└── hf-agents-course/      ← course material (your fork)
```

Keep repos **side by side, never nested**. A repo inside another repo's folder confuses Git about what to track.

## 6. The daily workflow

```bash
# --- get Hugging Face's latest course updates (see ⭐) ----------
gh repo sync <github-user>/agents-course   # updates your fork on GitHub
git pull                                   # brings it to your computer

# --- save your own work ----------------------------------------
git switch -c my-notes                     # new branch for your changes
git add .
git commit -m "Add my notes on unit 1"
git push -u origin my-notes                # first push of a branch
git push                                   # every push after that
```

Long form of the sync, the same as at work: `git fetch upstream` then `git merge upstream/main`.

## 7. Azure DevOps ↔ GitHub

| At work (Azure) | On GitHub |
| --- | --- |
| one shared repo, everyone branches | fork for other people's projects, branch inside it |
| PR from branch to `main` | PR from branch to `main`, **or** from your fork to upstream |
| `git pull` / `git push` | identical |

## 8. Common errors → fixes

| Error | Meaning | Fix |
| --- | --- | --- |
| `sudo: 'app': command not found` | typo | `sudo apt ...` |
| `Failed opening a web browser ... xdg-open` | WSL has no browser | open the URL in Windows and type the code |
| `git config --global user.email` prints nothing | no global identity set | §3 step 3 |
| commits not linked to your profile | the email in Git ≠ an email on your GitHub account | check with `gh api user --jq .id` (§3) |
| `push declined due to email privacy restrictions` | commit made with your real email | set the noreply email, then `git commit --amend --reset-author` |
| `Permission denied` pushing to `huggingface/...` | that's upstream, not yours | push to `origin` (your fork) |
