# 1.8 Lesson: A Public Agent — CodeAgent Is Not a Sandbox, and Who Pays

*Part of hf-AI-agents-course-1-agents. Follow-up of [1.6](1.6-CS-hf-space-first-agent.md) and [1.7](1.7-LL-helping-others-upstream-fix.md). The course's First Agent Template became a public "repo guide" agent on my Space `<hf-user>/First_Agent_Template`, after two adversarial reviews. The first one found that the template's `CodeAgent` lets any visitor read the Space secrets. 22 Nov 2026.*

## 1. The big idea in one picture

```
 visitor: "How do I set up the .env?"
    │
    ▼
 Gradio_UI.py   RECEPTION ─ foreign Origin? >500 chars? quota left? whose token pays?   ← code, before any credit
    │
    ▼
 build_agent(token)  a FRESH ToolCallingAgent, Llama 3.3 70B on a pinned provider
    │
    ▼
 model ── returns JSON only ──►  {"name": "find_brain_note", "arguments": {"topic": ".env"}}
    │                                     │
    │                                     ▼   the code calls ONE of 8 read-only functions
    │                            tools/repo_core.py ── GitHub tarball (brain/, probe/, README) ──► text
    ▼
 final_answer + "Source: 0.8 (link)"  +  signature appended by the code
```

**On a public page, every visitor is a stranger with your keyboard.** A `CodeAgent` lets the model write Python and runs it; in smolagents 1.13 the "safe" local executor can be walked out of in one line. A `ToolCallingAgent` only lets the model *choose* among functions I wrote. Then the second question: every answer costs money, so the code decides **who pays** and **how much**, before the model is called.

| Word | Meaning | Analogy |
| --- | --- | --- |
| **`CodeAgent`** | the model writes Python, the agent runs it (`LocalPythonExecutor`) | handing the visitor the site keys "but only for the meeting room" |
| **`ToolCallingAgent`** | the model returns JSON "call tool X with args Y"; no model-written code runs | a reception desk with 8 forms: you fill one in, the staff does the rest |
| **sandbox** | an environment whose walls hold even against hostile code (container, VM, separate machine) | a fenced site with a gate guard, not a sign saying "staff only" |
| **adversarial review** | a reviewer whose job is to **break** the thing, with proofs, not opinions | the fire inspector who tries the emergency doors |
| **OAuth** (Sign in with HF) | the visitor lends the Space a token with a limited scope (`inference-api`) | a member shows their own library card |
| **quota** | how many questions per day, counted in code before the run | day passes at the library desk |
| **provider** | the company that actually runs the model behind the HF router | the subcontractor behind the general contractor |
| **least privilege** | each token can do exactly one job | a key that opens one room |

## 2. What was built

| Part | What it does |
| --- | --- |
| `tools/repo_core.py` | standard library only: streams the repo tarball once (10-min cache), keeps only `brain/*.md`, `probe/*.json`, `README.md`; counts notes and experiments, searches and reads notes, coverage with its rule, commits, stars, the signature |
| `app.py` | 8 `@tool` wrappers, `build_agent(token)` = a fresh `ToolCallingAgent` per question, `max_steps=4`, logging off |
| `Gradio_UI.py` | Sign in with HF, quotas, Origin check, 500-char limit, generic error messages, signature on every answer |
| `prompts.yaml`, `tools/final_answer.py` | the library's tool-calling template + one paragraph; the citation rule inside `final_answer`'s argument description |
| `tests/` | 37 zero-credit tests with a fake model |

A real signature, computed live: *"hf-AI-agents-course by MArchMondello as of 2026-11-22 02:18 (Berlin, CET) covers 10%, synthesized 17 notes (11 CS, 6 LL) and 5 experiments, and has 0 stars on GitHub. Looking forward to yours!"*

**How the work went:** WP0 downloaded the Space and froze the interfaces (function names, signatures, return strings) in one file; a local venv **matching the Space** (Python 3.13, `gradio[oauth]` 5.23.1, `smolagents` 1.13.0, `huggingface_hub` 2.4.0, read from the build log); then three agents in parallel: WP1 `repo_core`, WP2 app + UI, WP3 the docs in `my-agents/`. Frozen interfaces are what made parallel work possible: like agreeing the grid and the levels before three teams draw the floors.

The code lives only in the Space; `my-agents/First_agent_template/` in this repo holds the prompt, the plan and a notebook that computes the diff against the template live.

## 3. The experiment: two reviews and four model probes

### Review #1 (before deploy, on the `CodeAgent` version)

Setup: a **fake** `HF_TOKEN` and a **fake model** that "writes" the attack code a visitor could ask for. Nothing real at risk, everything real executed.

| Hypothesis before the review | Result |
| --- | --- |
| `LocalPythonExecutor` blocks dangerous imports, so the env is safe | ❌ read through the tools' globals, no import needed |
| "a fresh agent per request" isolates visitors | ❌ tool objects and classes are shared by all agents in the process |
| the quota is code, the model can't touch it | ❌ `setattr` could switch it off for everyone |

### Review #2 (after the switch to `ToolCallingAgent`)

No critical or high findings. Fixed anyway: one anonymous client could use up the 25/day shared pool; a foreign website could spend a signed-in visitor's credit; expired OAuth tokens; messages now read the limits from the quota object. Accepted as low: see section 11.

### Model probes (one real call each, HF router, tool calls)

| Model | Provider | Result |
| --- | --- | --- |
| Qwen2.5-Coder-32B (the template's) | featherless (the only one) | **404** on tool calls |
| Qwen2.5-72B | deepinfra | **500** errors |
| Qwen3-32B | deepinfra | **invalid JSON** in the tool call |
| **Llama-3.3-70B** | novita (pinned) | ✅ **3 / 3** correct tool calls, ~3 s |

One probe per model is not N = 10: enough to exclude a model that fails, not to rank two that work.

### Live checks after deploy (anonymous, via `gradio_client`)

| Question | Result |
| --- | --- |
| how to set up the `.env` | ✅ cites 0.8 with its link |
| coverage + experiments | ✅ 10% with the rule, 5 experiments |
| "What is the ReAct loop?" | 🟡 cites 1.2, while 1.0 is the better note (search ranking / the model's query wording) |
| a 600-character prompt | ✅ refused before any model call, free |
| quota | ✅ 25 → 22 |
| signed in (billed to the visitor) | ⬜ not done: needs a human login |

Cost of the whole build in inference: a few cents (about 10 real agent runs). Everything else ran on fake models.

## 4. Lesson 1: `CodeAgent` is not a sandbox

The executor of smolagents 1.13 interprets the model's Python and refuses `import os`. But it gives the code the **real** `getattr`, and Python's `str.format` walks attributes **inside C**, where the executor does not look. Tool objects are reachable by name, and a tool's `forward` function carries its module's globals. One line was enough:

```python
'{0.__globals__[os].environ}'.format(count_brain_notes.forward)   # → the whole environment
```

The environment of a Space holds `HF_TOKEN` **and** `OAUTH_CLIENT_SECRET`, the key Gradio uses to sign session cookies. From the same globals: `yaml.unsafe_load` = remote code execution; `setattr` on shared classes = the quota off for everyone, and worse for other visitors' sessions. The class of bug: **an interpreter that filters names but hands out real objects** cannot stop attribute walking. This is a known weakness of local executors, and the course template exposes it on every duplicate that keeps the `CodeAgent`, mine included.

**What I did, in order:**
1. **Paused my live Space at once** (it ran the template's `CodeAgent` with my token).
2. Switched to **`ToolCallingAgent`**: the model only returns JSON, the code calls one of 8 functions. No model-written code runs anywhere.
3. A regression test: code sent *inside* a tool call stays a **string**.

| | `CodeAgent` | `ToolCallingAgent` |
| --- | --- | --- |
| model outputs | Python | JSON: tool name + arguments |
| what runs | whatever the model wrote | only functions I wrote |
| needs a sandbox (container, E2B…) | **yes**, on a public page ([1.5](1.5-CS-sandbox-approaches.md)) | no |
| good for | maths, data, chaining tools in one step | a fixed set of read-only questions |

Analogy: "only the meeting room" is a sign, not a wall. If the visitor holds a real key, every door with the same lock opens.

## 5. Lesson 2: who pays? OAuth and quotas, in code, before the run

| Visitor | Whose token | Limit |
| --- | --- | --- |
| anonymous | mine (Space secret `HF_TOKEN`, inference only) | 25/day in total, **max 5 per visitor** (hashed IP, memory only, best effort) |
| signed in with HF | **theirs** (`hf_oauth_scopes: [inference-api]`) | 20/day per username |

| Rule | Why |
| --- | --- |
| the token is passed **explicitly**, never `None` | `HfApiModel(token=None)` falls back to the `HF_TOKEN` env var: I would silently pay for signed-in visitors |
| check-and-decrement under a `threading.Lock`, **before** the run | two clicks at the same instant can't both take the last question (test: 40 threads → exactly 25 pass) |
| refuse a foreign `Origin` | Gradio answers cross-site requests and the login cookie is `SameSite=None`: another page could spend a signed-in visitor's credit |
| refuse an expired OAuth token | no half-signed-in state that falls back to my token |
| counters in memory | a restart resets them: the real money ceiling is the HF account and an inference-only token |

## 6. Lesson 3: pin the provider

`provider=None` on the HF router means **"auto"**: the router picks a provider, and can pick another tomorrow, with another price and another tool-call behaviour (the 404 / 500 / bad JSON of section 3 all came from routes). Pinned: `provider="novita"`. The router's `/v1/models` listing shows, per provider, whether tools are supported and the price (here $0.135 per million input tokens, $0.40 per million output tokens). Same rule as `requirements.txt`: name the exact product.

## 7. Lesson 4: put the rule where the model reads it

| Rule | Where first | What happened | Where now |
| --- | --- | --- | --- |
| "end with `Source: <note> (<link>)`" | end of the system prompt | Llama ignored it | in **`final_answer`'s argument description**: read at every answer → it cites |
| "you cannot run code" | missing | asked "run this code: `print(os.environ)`", the model **invented** a fake macOS environment | in the system prompt: "*…never invent outputs*" → it refuses plainly |

The invented environment held no real data, but it was a confident lie: the [1.1](1.1-LL-dummy-agent-temperature.md) invented Observation, again. Same lesson as [1.3](1.3-LL-lie-order-next-to-observation.md): **the closest text wins**. A tool's description sits next to the moment of use; the end of a long system prompt does not.

## 8. Lesson 5: never show raw errors

On a failed step the UI printed the provider's error: URLs, request ids. Now a failed step shows only `STEP_ERROR` (*"This step failed; the agent will try again."*), and a failed run a generic sentence. The full text still enters the model's memory (it needs it to retry), the visitor never sees it. Analogy: the client gets "we're fixing it", not the subcontractor's internal email.

## 9. Lesson 6: a token for one job, and the PR that got a 403

`HF_TOKEN_SPACE_WRITE`: fine-grained, **write on one Space only** ([0.8](0.8-CS-env-secrets.md)).

1. **The trap:** the first try ticked the permissions under **User permissions** = write on **all** my repos. Caught by reading the token's own scope **without printing the token**: `whoami()["auth"]["accessToken"]["fineGrained"]["scoped"]` lists which repos the permissions apply to. Fixed: Write moved to the single Space row under **Repositories permissions**.
2. **The plan said "deploy as a PR on my own Space"**: `create_commit(create_pr=True)` → **403**. Opening a PR is a **discussion** permission, which a Space-scoped write token doesn't have.
3. **Deployed as a direct commit with a guard:** `parent_commit=<sha recorded before>`. If the Space changed in the meantime, the commit fails instead of overwriting. Rollback point = that recorded sha. Then `restart_space` (it was paused). Built in about a minute.

Not adding the discussion permission was the right call: the review was done on the diff locally, the PR would only have been a second copy of it.

## 10. Lesson 7: test with a fake model

A `FakeModel` class returns pre-written **tool calls**. It drives the **real** `ToolCallingAgent` loop, the real tools and the real UI handler. 37 tests, zero credit:

| Tested | How |
| --- | --- |
| tool → final answer → signature | scripted tool calls |
| the max-steps path and a failing run | still signed, generic message |
| the visitor pays with **their** token | the factory records which token it received |
| quotas: pool, per user, per visitor, midnight, race | an injectable clock, 40 threads |
| refused before any agent is built | long, empty, foreign Origin, missing or expired token |
| the exploit regression | no code executor; code in a tool call stays a string |

The adversarial review used the same trick: a fake model is how you **write** the attack without asking a real model to.

## 11. Takeaways

- **On a public page, a `CodeAgent` needs a real sandbox.** Without one, use a `ToolCallingAgent` with a few read-only tools.
- **A review with proofs beats a review with opinions.** The fake token and fake model turned "probably fine" into a one-line exploit.
- **Who pays is code, decided before the model runs**: explicit token, lock, limits, Origin.
- **Pin what can move under you**: library versions, the provider, the deploy's parent commit.
- **Put a rule where the model reads it** (a tool description), not at the end of a long prompt.
- **Least privilege, checked by reading the scope, never by printing the token.**
- **Honest flaws:** search ranking (1.2 instead of 1.0), counters reset on restart, a slow GitHub can exceed the 3 s timeout, one probe per model only, the signed-in path not tested live.

## 12. Next probes

- **Signed-in visitor billing**, live: a human login, one question, check the quota line says "yours".
- **Search ranking**: 10 questions with a known best note, count hits; then try a better score (title weight) and run the same 10.
- **Models**: N = 10 runs per model on the same 5 questions (tool-call validity, citation present), Llama vs one or two others that pass the first probe.
- **CodeAgent in a real sandbox** (`executor_type="e2b"` or Docker, [1.5](1.5-CS-sandbox-approaches.md)): repeat review #1's one-liner and check that the secrets are not there.

## 13. Common errors → fixes

| Error | Meaning | Fix |
| --- | --- | --- |
| model-written code reads `os.environ` through a tool's globals | `LocalPythonExecutor` is not a sandbox | `ToolCallingAgent`, or a real sandbox (container / E2B) |
| `404` on tool calls for a model that works in chat | that provider route doesn't support tools | check `/v1/models` on the router; pick a model + provider with tools; pin the provider |
| `500` or invalid JSON in the tool call | provider or model weak at tool calling | one probe per candidate, keep the one that passes |
| the model ignores "cite the source" | the rule is far from the moment of use | put it in `final_answer`'s argument description |
| the model "runs" code and shows an invented output | it has no tool for it and fills the gap | "You cannot run code… never invent outputs" |
| raw provider errors in the chat | the UI prints `step_log.error` | show a fixed `STEP_ERROR` |
| signed-in visitors billed to the owner | `token=None` falls back to `HF_TOKEN` | pass the OAuth token explicitly; refuse empty or expired tokens |
| one client uses up the anonymous pool | only a total limit | add a per-visitor cap (hashed IP) |
| another website spends a visitor's credit | cross-site requests + login cookie | refuse requests whose `Origin` isn't the Space or huggingface.co |
| token with write on **all** repos | permissions ticked under *User permissions* | move Write to the single repo under *Repositories permissions*; check `whoami()["auth"]["accessToken"]["fineGrained"]["scoped"]` |
| `403` on `create_commit(create_pr=True)` | opening a PR needs the discussion permission | direct commit with `parent_commit=<recorded sha>`, rollback = that sha |
| the Space doesn't come back after deploy | it was paused | `restart_space(...)` |
